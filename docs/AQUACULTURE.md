# 공동 가두리 양식 v1.0

## 운영과 저장

기존 Worker `sea-multiplayer`, D1 `sea-game-db` / `DB`, `ROOM` / `SeaRoom`, WebSocket 프로토콜 2를 유지한다. 기존 익명 인증 토큰을 서버가 검증한 연결에서만 아이템 행동을 허용한다. 닉네임은 기존 `players` 레코드, 튜브 색상은 고유 Player ID에 연결한 `aqua_profiles`에 보존한다. 구버전 클라이언트의 이동과 기존 통계 API는 그대로 동작한다.

`0002_aquaculture.sql`은 별도 `aqua_` 테이블·제약·인덱스만 추가한다. 기존 플레이어, 방문 통계, 항해 시간, 관리자 비밀번호를 수정하거나 삭제하지 않는다. Worker 시작 후 상태 준비/첫 접속 때 기존 DB 바인딩으로 반복 가능한 마이그레이션을 적용한다. `/health`의 `aquaculture: ready`로 초기화를 확인할 수 있다. 마이그레이션을 위해 새 DB나 DO를 만들 필요가 없다.

## 플레이

1. 배에서 바다로 내려가면 튜브가 자동 장착된다. 수면 높이를 기존 바다 샘플러로 추적하며, 기존 이동·수영 모션을 사용한다. 점프 버튼으로 배에 복귀하면 튜브가 제거된다.
2. 배 양옆의 치어 군집 2m 이내에서 뜰채 버튼을 누른다. 서버가 시작/완료 시 수면 상태, 거리, 2초 경과, 15초 제한을 확인한다. 성공률 100%, 치어 최대 5마리. 공동 군집은 채집 후 30초 뒤 다시 나타난다.
3. 가두리 A(-40,-30), B(40,-42)는 각각 독립적이다. 가두리 주변에서 참여 후 치어 1마리를 방류한다. 인원은 각 3명, 한 플레이어는 가두리 한 곳만 참여 가능하다.
4. 방류부터 실제 서버 시간 12시간 동안 양식한다. 먹이는 최대 3회, 같은 플레이어는 마지막 먹이부터 3시간 대기한다. 가두리를 옮기거나 탈퇴·재참여해도 개인 쿨타임을 건너뛰지 못한다. 다른 참여자는 별도 대기 없이 줄 수 있다.
5. 완료 시 먹이 1회마다 해당 기여자에게 물고기 1마리를 배정한다. 먹이 0회인 양식은 보상 없이 종료된다. 보상 확정과 주기 종료는 하나의 D1 트랜잭션이다. 가두리는 다음 치어를 받을 수 있고 참여자는 그대로 유지된다.
6. 미수확 물고기는 개인 보관함에 계속 남는다. `양식·도감`의 수확 버튼으로 받으며, 한 번에 최대 20마리씩 지급한다. 누적 보상이 더 많으면 다시 수확할 수 있다. 최초 획득 시 도감에 컬러 아이콘이 등록되고 수량을 표시한다.

튜토리얼은 Player ID별 단계로 저장한다. 마지막 안내를 본 뒤 완료 상태를 저장하며 재접속 시 이어서 진행한다. 모든 표시 날짜는 KST, 남은 시간은 서버 시각과 브라우저의 단조 증가 시계를 사용한다. 브라우저의 날짜 변경은 서버 성장/보상 판정에 영향을 주지 않는다.

## 공동 관리와 정확성

- 참여·방류·먹이·수확은 하나의 공개 방 DO에서 직렬화한다. 참여자 PK, 정원 트리거, 가두리별 활성 주기 UNIQUE, 먹이 슬롯 1~3 제약으로 중복/초과를 방지한다.
- 클라이언트는 행동 의도와 요청 UUID만 전송한다. 서버에서 인증된 Player ID, 검증된 위치/수면 상태, DB 수량과 서버 시간을 사용한다. 요청 결과는 DB에 저장해 같은 요청 재전송에 다시 지급하지 않는다.
- 치어 차감·방류, 수확 인벤토리 증가·보상 수령 표시·요청 기록은 각각 원자적 D1 batch다. 실패하면 함께 롤백된다. 응답만 유실된 경우 같은 UUID로 재시도하여 이미 완료된 결과를 확인한다.
- 방류/먹이/수확 등 상태 변경 후 다른 연결에 갱신을 알린다. 개인 인벤토리는 본인에게만 전송한다. 위치·튜브 색상·수면 움직임과 채집/먹이 반응은 기존 WebSocket으로 전달한다.
- DO 알람은 통계 기록의 60초 주기와 다음 양식 완료/자리 해제 중 빠른 시각을 유지한다. 접속자가 없어도 완료를 정산하고, 재시작 후에는 DB 기준으로 복구한다. D1 장애 시 아이템 행동을 거절하고 기존 멀티플레이 이동은 계속 허용한다.
- 참여·방류·먹이·수확 이후 48시간 동안 양식 활동이 없으면 참여 자리만 해제한다. 조회만으로 자리를 연장하지 않는다. 직접 자리 비우기도 가능하다. 먹이 기록, 미수확 보상, 인벤토리와 도감은 지우지 않는다.

## 관리자 테스트

기존 `/admin` 페이지와 `ADMIN_PASSWORD` 인증을 재사용한다. 하단 `공동 가두리 관리`에서 참여자·먹이 기록 확인, 즉시 성장 완료, 치어 최대 5마리 지급, 테스트 초기화를 제공한다. `/admin/aqua`의 GET/POST는 모두 관리자 인증과 Origin/요청 제한을 검사한다. 일반 WebSocket에는 관리자 명령이 없다.

초기화는 해당 가두리의 양식을 종료하고 참여 자리만 비운다. 이미 쌓인 먹이 기여를 먼저 보상으로 확정하므로 기존 보상과 개인 인벤토리를 삭제하지 않는다. 관리자 명령도 요청 UUID로 중복을 막고 기록한다.

## 검증 및 배포

`npm run test:server`로 실제 Miniflare D1/DO 런타임에서 동시 3인 참여, A/B 독립, 2초 채집, 3시간 제한, 12시간 보상 배분, DB 실패 롤백, 응답 유실 후 중복 방지, 48시간 자리 해제, 관리자 인증·명령 및 기존 멀티플레이를 검사한다. 게임은 `npm run build` 후 기존 GitHub Pages 경로로 배포한다. Worker는 `npm run server:deploy -- --keep-vars`로 기존 비밀값과 DB/ROOM을 보존한다.
