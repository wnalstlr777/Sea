# Sea 플레이어 기록 v0.1

기존 Worker `sea-multiplayer`, SQLite Durable Object `ROOM` / `SeaRoom`, 프로토콜 2와 최대 20명 정원을 유지한다. D1 `sea-game-db`는 `DB`로 바인딩한다. 게임·랭킹 UI는 추가하지 않는다.

## 배포와 마이그레이션

`wrangler.jsonc`에 실제 D1 ID와 로컬 바인딩을 함께 명시했다. `server/migrations/0001_player_records.sql`은 CREATE TABLE / INDEX / TRIGGER IF NOT EXISTS만 포함한다. 재실행해도 기존 데이터와 누적 기록을 지우지 않는다.

Worker의 첫 기록 요청에서 DB 바인딩을 통해 마이그레이션을 적용한다. 먼저 기존 4개 테이블의 컬럼을 확인하고, 다른 스키마와 충돌하면 데이터를 변경하지 않고 기록 API에 503을 반환한다. 게임 연결은 계속 허용한다. D1 관리 API 권한이 없는 배포 토큰도 기존 DB 런타임 바인딩을 사용할 수 있다. 관리 권한이 있는 환경에서는 `npx wrangler d1 migrations apply sea-game-db --remote --env=`로 같은 SQL을 적용해도 안전하다.

검증: `node server/tests/records.test.js`, `npm run test:server`, `npm run build`.
배포: `npm run server:deploy` 후 main push로 GitHub Pages 클라이언트를 배포한다. DO 클래스/마이그레이션 v1은 그대로 둔다. DB를 새로 만들거나 교체하지 않는다.

## 식별과 세션

- `POST /identity`에서 서버가 Player ID와 무작위 비밀 토큰을 발급한다. D1에는 토큰의 SHA-256만 저장한다. 기존 토큰과 ID가 일치할 때만 같은 플레이어를 반환한다.
- 브라우저 `localStorage['sea.player.v1']`에 ID와 토큰을 저장한다. 저장소 삭제·다른 기기는 새 플레이어다. Web Locks 지원 브라우저에서는 동시 첫 방문 탭의 발급도 직렬화한다.
- 토큰은 WebSocket 서브프로토콜로 전달하고, URL·공개 플레이어 목록·랭킹에는 넣지 않는다. 계정 로그인은 아니며 토큰을 가진 브라우저를 같은 익명 플레이어로 취급한다.
- 기존 한국어 자동 닉네임 목록에서 발급한 닉네임을 계속 사용한다. 접속 국가만 `request.cf.country`에서 가져오며, 알 수 없으면 UNKNOWN이다. 클라이언트 국가 헤더는 덮어쓴다. IP 원본은 D1에 저장하지 않는다.
- 네트워크 아바타 ID는 연결별 고유 ID를 유지한다. 같은 Player ID로 여러 탭을 열어도 기존 아바타·위치·애니메이션 동기화가 충돌하지 않는다.
- 새 탭/새로고침/새 방문은 새 서버 발급 세션이다. 자동 재연결은 메모리에 있는 세션 ID를 재사용한다. 같은 플레이어의 세션이며 마지막 접속 이후 120초 이내인 경우에만 이어 쓴다. 임의 세션 ID는 새 서버 세션으로 교체한다.
- 동일 세션 재시도는 횟수를 올리지 않는다. 여러 탭의 다른 세션은 각각 접속 1회이지만, 같은 KST 날짜의 순 방문자는 1명이다. 방문 날짜는 세션 시작 시각 기준이며, 단순히 자정을 넘겨 접속을 유지한 것만으로 새 방문을 만들지 않는다.

## 저장과 장애 처리

4개 테이블: `players`, `daily_stats`, `daily_visitors`, `visit_sessions`. 세션 PK와 날짜·플레이어 복합 PK로 중복을 막는다. INSERT 트리거가 누적·일별 접속 및 순 방문자를 함께 갱신한다. 시간은 밀리초로 보관하고 조회 시 초 단위로 반환한다.

60초 DO 알람 및 접속/종료 이벤트에서만 기록하며 매 프레임 D1 쓰기는 없다. 여러 탭의 접속 구간을 플레이어별로 합집합 처리한다. 자동 재연결 중 끊어진 구간은 항해 시간에 더하지 않는다. 마지막 메시지/하트비트 이후 75초를 넘긴 연결은 종료하며, 비정상 네트워크 단절 시간은 이 유예 범위 안에서만 추정된다.

D1 전송 전에 DO 저장소에 기록 대기열을 남긴다. 장애 후 재시도 시 세션 PK와 플레이어의 기록 완료 시각으로 중복 누적을 막는다. 이미 검증되어 연결된 플레이어의 대기 기록은 복구 후 반영한다. D1 장애 때문에 새 브라우저 식별 자체를 검증할 수 없는 경우에는 익명 멀티플레이 연결을 허용하되 해당 연결은 통계에서 제외한다. 기존 구버전 클라이언트도 게임은 유지하지만 식별 기능이 없으므로 방문 기록에는 포함되지 않는다.

7일 지난 상세 세션만 정리한다. 이 시점의 세션은 120초 재연결 허용 범위를 지났으므로 재사용할 수 없다. 플레이어, 누적 시간/횟수, 일별 집계와 순 방문자 기록은 삭제하지 않는다. 관리자 초기화 API/UI는 만들지 않는다.

## 읽기 API

서버 주소: `https://sea-multiplayer.wnalstlr777.workers.dev`.

- `GET /stats`: `dateKst`, `todayVisits`, `todayUniqueVisitors`, `totalVisits`, `currentConnections`, `currentPlayers`.
- `GET /rankings?kind=sailing`: 누적 항해 시간 TOP 10.
- `GET /rankings?kind=visits`: 누적 방문 횟수 TOP 10.
- 순위 항목: `nickname`, `countryCode`, `sailingSeconds`, `visits`. 비밀 토큰과 Player ID는 공개하지 않는다.
- 동점 순서: 최초 접속 시각 오름차순 → Player ID 오름차순. 빈 기록은 빈 배열이다.
- `currentConnections`는 살아 있는 연결 수, `currentPlayers`는 검증된 Player ID 기준 중복 제거 수다. 식별되지 않은 구버전/장애 연결은 연결별 1명으로 계산한다. D1에 실시간 접속자 수를 저장하지 않는다.
- 집계 캐시는 10초, 랭킹 캐시는 30초이며 현재 접속 수는 매번 DO 연결에서 계산한다. 항해 시간은 최대 기록 주기만큼 늦게 보일 수 있다.
- 데이터 API/식별은 IP별 분당 30회, 연결은 분당 60회, 엔드포인트별 전체 300회 제한이다. IP 키는 메모리 안의 임시 솔트 해시만 사용한다. 초과 시 429, D1 장애 시 503이다. DO 재시작 시 일시적인 제한·조회 캐시는 초기화된다.
- 다른 브라우저 Origin은 기존 허용 목록으로 거절한다. 임의 누적 시간/횟수를 받는 API와 개인 플레이어 조회 API는 없다.

## 관리자 대시보드

운영 주소: `https://sea-multiplayer.wnalstlr777.workers.dev/admin`.

Cloudflare에 기존 등록된 `ADMIN_PASSWORD` 비밀값으로 로그인한다. 비밀번호는 변경하거나 클라이언트 코드에 포함하지 않는다. HTTPS Authorization 헤더로만 전달하며, 브라우저 저장소·URL에는 저장하지 않는다. 페이지 종료/로그아웃 시 메모리 인증값과 표시 데이터를 지운다. 비밀값이 없으면 접근을 거절한다.

관리자 데이터는 `GET /admin/data?days=7` 또는 `days=30`에서만 제공한다. 모든 요청에서 인증하고, 같은 Origin만 허용하며 응답을 브라우저에 캐시하지 않는다. 기존 요청 제한을 관리자용 별도 구간으로 적용한다. 로그인 화면 자체에는 통계나 인증값이 포함되지 않는다.

- 오늘 접속자: KST 오늘 순 방문자. 현재 항해자는 별도 상태로 표시한다.
- 누적 방문자: 접속 횟수가 1회 이상인 고유 플레이어 수. 식별값만 발급받고 방문하지 않은 기록은 제외한다.
- 오늘 방문 횟수: 기존 일별 접속 세션 집계.
- 누적 항해 시간: 방문한 모든 플레이어의 저장된 누적 항해 시간 합계.
- 추이: 최근 7일/30일의 일별 순 방문자와 방문 횟수. 기록이 없는 날짜는 0으로 채운다.
- 랭킹: 기존 항해 시간/방문 횟수 TOP 10 조회를 그대로 재사용한다.

자동 갱신은 30초 주기이며 화면이 숨겨진 동안 멈춘다. 서버 집계 캐시는 10초이며 항해 시간 저장 주기(최대 60초)가 추가로 반영된다. 갱신 실패 시 마지막 성공 데이터를 유지하고 안내를 표시한다. 대시보드는 조회 전용이며 플레이어·게임 상태나 기록을 수정하는 기능은 없다.
